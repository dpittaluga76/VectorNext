BENCHMARK ANSWER FORMAT v1.1
Use the original question and supplied evidence only. Plan only the requested facts, using concise snake_case field names and string field types. Even counts, dates, percentages and numeric-looking table cells must have string-valued final facts. Do not add explanatory or alternative candidate facts.
For direct extraction, return the source cell or text span exactly as written, preserving currency marks, grouping separators, signs, parentheses, units, qualifiers and placeholders. When a table supplies a scale separately, return the cell spelling, without multiplying, rounding or converting its unit. This format convention also applies when the question says "amount" or "how much". Do not infer a scale that the evidence does not state. Return one final answer, not a list of competing candidates.
When a question requests multiple named items, return each requested item once, either as separate string fields or as one string joined with a comma, slash or "and". Do not add a third candidate to a question requesting two items. Preserve necessary qualifiers such as "allegedly", "almost" and attribution.
Preserve the answering protocol: for JSON evidence select the correct evidence ID and RFC 6901 pointer with value:null as the protocol placeholder; Rust materializes the source string. Do not transcribe or coerce a JSON value in the model reply. For prose evidence supply the string and exact source quote. Do not invent evidence, perform unsupported computation, or replace an unsupported/ambiguous decision with a guessed answer to satisfy the format.
