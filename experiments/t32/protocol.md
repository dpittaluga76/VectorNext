# T32 — 24-request replacement pilot

Freeze before measured questions: six fresh synthetic questions × four combinations, one pass, **24 total scored requests**. No historical quality replays, retries of failed measured answers, prompt tuning or additional quality batches. Preflight/unit tests use separate synthetic input and are reported separately.

The ten fictional sources include six TXT, two JSON and two visually reviewed one-page PDFs. The six questions cover revision/distractor resolution, two-document facts, an exact large integer in a longer JSON record, unknown versus zero, a PDF correction and separate PDF counts. `requests.json` contains only public questions/field definitions; `gold.json` and the literal-source scorer are never sent to inference. `input-freeze.json` binds source/request/label bytes. Do not regenerate them during tests. This is a small author-created pilot, not independent quality validation.

Profiles: baseline MiniLM embedding/reranker; Nomic v1.5 publisher FP32 ONNX at 768 dimensions with masked mean → layer norm (epsilon 1e-5) → L2, query/document prefixes and a tested 1,024-token limit; Ettin-17M publisher ONNX token backbone plus pinned CLS/Dense/GELU/LayerNorm/Dense head and raw logits. Both rerankers retain the same 512-token pair cap. Pin/checksum all artifacts, including head weights/configuration. Reject truncation, missing/corrupt files, invalid dimensions/nonfinite values and unknown profiles. Preserve exact legacy space/reranker identities.

Use current retained API `vectornext-app:t28-12b` and current `12b`/f16/two-call normal generator (same image/command across arms). Only the test processor changes. No normal library/default/image changes. The isolated API/processor use dedicated storage/cache volumes and port 8101. The processor connects to the normal generator's existing internal network/scheduler; no new GPU model, generator restart or unrelated-workload interruption. Freeze normal image IDs/commands, candidate image, code, input and model locks before measured queries; retain a source ZIP.

Ingest all ten documents once per embedding profile with structural context and the normal 180-token target. Reject/retain failures and keep all applicable questions in their denominator. Reuse the same committed database for its two rerankers, checked by exact document snapshots. New processor/API processes and an empty query cache per arm. One common synthetic warmup per arm exercises the worker/reranker/Gemma and is outside scored timing, using no pilot source/question. Fixed public question order, no mutation between arms. Order: MiniLM/MiniLM → Nomic/Ettin → Nomic/MiniLM → MiniLM/Ettin; this balances changes but is not statistical counterbalancing with repeats. Do not claim OS-cache isolation.

Capture raw response bytes/status/transport failures and timings before scoring. Score exact validated field values and intended status; supported positives additionally require original-document source coverage for every labelled fact. Unknown-count success requires insufficient_evidence, not a fabricated zero. Report literal coverage over raw candidates, selected 20, final five and assembled evidence separately from answer correctness. Historical or newly discovered alternative label readings are separate notes, never changed gold. Include source admission, chunk counts, embedding/rerank/answer timings, overall median/p95, sampled container memory/CPU and ingestion cost. Six-request p95 is descriptive only. No fresh long-context/quality assertions from unit boundaries alone.

Retain all 24 outcomes and every attempted failure. Resume only unattempted work under matching frozen identities; never retry measured failures into success. Stop only the dedicated API/processor after testing, preserve volumes/caches and compare normal library/readiness. No default switch on six questions: a no-loss improvement supports a follow-up recommendation only. No numerical quantization, chunk enlargement, approximate indexing, API/schema changes, production migration or unused holdout use.
