# Model ingestion contract (T07)

This extends architecture sections 6, 8, and 9. Rust remains the sole database writer. A persistent Python child handles CPU tokenization/embedding and calls the isolated llama.cpp container for generation. The internal JSON-lines interface carries text/configuration, never a database handle. The child shares the CLI container's filesystem permissions; it is a dependency boundary, not a security sandbox. T08 adds generation priority; T09 adds [separate application services](deployment.md), preserving this worker/model contract while removing the processor’s database mount.

An optional versioned context configuration preserves serialization of T05/T06 jobs. `plain` embeds evidence; `structural` embeds structure and evidence; `generated` adds a separately stored annotation. All policies preserve source structure for inspection. Comparisons of keyword retrieval must explicitly select matching field weights: the T04 index defaults do not change automatically with ingestion policy.

The generated policy reserves 64 of MiniLM's 256 tokens during chunking, including separators in the eventual exact input check. It enriches prose/list chunks only; headings, tables, and explicit JSON retain structural context without generation. The first selection policy is deliberately simple and measurable, not a claim that every selected chunk needs enrichment.

Generation receives the whole parsed document if it fits the 8,000-byte scope bound; otherwise it receives exact chunk spans, mandatory parent-heading/PDF context source blocks, and complete nearby blocks within that bound. The scope records block spans and source references. The worker checks the actual rendered Gemma prompt plus 256 output tokens against 4,096 tokens. An oversized request fails explicitly; evidence is never silently truncated. Annotation output is schema constrained at temperature zero, limited by the embedding tokenizer, and checked again in the complete embedding input. Empty context is an explicit supported outcome. Source links establish provenance of supplied context, not factual entailment of generated prose.

The durable context report records each eligible chunk's complete generation-input digest, chosen scope, and outcome. The ingestion configuration pins model artifacts, runtime, prompt text/hash, selection/input versions and sampling parameters. Rust validates report identities, scope, permitted stage mutations, and generated metadata before accepting a stage. Failures leave the last successful stage durable; no partial revision becomes searchable. Chunk-level model caches avoid repeating successful inference after a failed stage.

Disposable disk cache keys include operation, exact input, full model/preprocessing identity, and generator configuration where relevant. Cache values use checksummed atomic files with bounded total size; corrupt entries are misses. Embeddings are still stored durably in committed revisions. Cache deletion or model outages do not affect existing database reads. Real-model verification uses source fixtures only, without evaluation questions or gold answers.

The worker reuses the pinned T02 encoder implementation directly; it does not import benchmark prompts or labels. Its space identity includes the artifact, tokenizer checksum/runtime, ONNX/NumPy versions, mean pooling and normalization conventions. Generation startup verifies the GGUF checksum before launching the pinned binary. This is trusted local tooling, not remote attestation of an arbitrary model endpoint. Do not override the endpoint with a different model while keeping the saved identity.

Limits: one synchronous worker per CLI, 1 MiB encoder text, and 4 MiB JSON-lines frames/replies. T08 extends worker deadlines to 420 seconds (720 for two-stage answers) and individual HTTP deadlines to 215 seconds to cover bounded queue admission plus backend work. The [answer contract](answers.md) defines the scheduler's shorter queue/backend deadlines and interactive priority; T07 generation/cache identities are preserved. Large pathological source blocks can fail these bounds even below the parser's 16-MiB file limit. Token counts are exact; CPU inference uses one text per call and four ONNX threads. Cancellation, durable model queues, adaptive context selection, and throughput tuning remain later work. Cache locking serializes file operations only; concurrent duplicate inference is possible. Model/cache identities are conservatively invalidated by revision-scoped source references, so identical text from unrelated revisions may regenerate annotations while sharing identical embeddings.
