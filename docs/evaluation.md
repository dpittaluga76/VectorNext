# T10 evaluation protocol

Status: complete, 2026-10-14. The initial protocol was registered before comparison; subsequent clarifications and trials are explicitly recorded below. Results: [T10 report](reports/t10-evaluation.md) and [JSON evidence](reports/t10-evaluation.json). Design reference: architecture section 10 and [measurement contract](../evals/metrics.md).

Compare `plain`, `structural`, and `generated` context on the unchanged five T01 source files, using the same pinned MiniLM embedding/reranking models and Gemma 4 26B A4B QAT Q4_0, temperature 0, 22 CPU expert layers and 4,096-token context. Keep document IDs, chunk target, source hashes, 30/20/5 candidate/rerank/primary limits, prompts and answer field schemas fixed. Generated policy's existing token reservation can change chunk boundaries; report this rather than claiming an identical-chunk ablation. No generated text is evidence.

Use only the 13 `dev` cases. A separately declared public request map supplies field names/types and the original question/history/template; expected values, evidence IDs, support sets and outcome labels never enter requests or indexed sources. The six holdout questions remain unused, including model prompts. Scoring reads labels separately after response capture. Do not regenerate sources or labels.

Use a dedicated `vectornext-t10` Compose project/volume and port 8089; preserve T07/T09 data. Run policy-specific databases and disposable cache namespaces sequentially, with one GPU model service. Record process/model startup separately. For each policy, measure complete ingestion including PDF preparation and actual context/embedding calls. For query comparison, restart API/CPU processes with an empty cache namespace, then run all 13 questions once (`cold-cache pass`) and repeat unchanged (`warm-cache pass`). Weights are already loaded when queries begin, CPU readiness includes a synthetic reranker warmup, and OS file caches are uncontrolled. These are not physical-disk cold starts. Report all failures and timing scopes.

Instrument monotonic stage timings, GPU queue/backend time, CPU operation time and sampled container/device memory. The host runner records complete API latency and polling/startup overhead. Separate overlapping/nested times; do not sum them as wall time. Raw responses retain candidates, actual source references, final context and model audits. Memory sampling records its interval and includes other device usage; it cannot prove a true instantaneous peak.

Score evidence by original document/hash and source coverage: TXT byte interval union; JSON pointer ancestry or collective coverage of all gold subtree leaves with exact types/values; PDF same-page geometry compatibility plus complete normalized expected text in source evidence. T01's PDF boxes are broad selection regions including whitespace, not tight text bounds: use intersection divided by the smaller rectangle area of at least 0.8, with a 2-point tolerance on returned boxes, rather than demanding coverage of blank page area. Keep geometric location matches and text fidelity separate; only both together earn PDF evidence credit. Report dense/keyword/fused/reranked recall, complete-support rate, first complete rank and final assembled context. Supported cases use their OR-of-AND support sets; ambiguity requires all alternatives; missing-evidence recall stays undefined. No nDCG or authoritative precision without exhaustive relevance labels. This rule was refined against the source locator definitions before any T10 comparison result.

Report exact typed fields/status/template separately from mechanical validation and manual factual support. Inspect every distinct supported answer's quoted/pointer evidence against the source, recording reviewer notes. Record prompt/evidence size, repeated source spans and non-gold source text as descriptive proxies, not authoritative irrelevance labels.

Tune only in response to observed development losses/costs. Candidate-budget/reranker/field-weight ablations may use captured query vectors and source records for inexpensive retrieval measurements before selected end-to-end confirmations. Retain the baseline and every attempted change. Prefer the cheaper policy if quality ties; do not add approximate indexes or extra services without a measured bottleneck. Any improvement remains development-set evidence; no state-of-the-art or 400-document scaling claim follows from this corpus.

## Recorded clarification during baseline analysis

The inherited application's keyword index uses evidence/structural/generated weights 1/1/1 regardless of the ingestion policy. Stored structural fields must remain available for source expansion even under plain embeddings. Therefore the initial three `baseline` runs compare ingestion/embedding policies with keyword weights held fixed; the plain baseline is **plain embeddings with structural keywords**, not fully plain retrieval. Preserve those runs. Add `plain/evidence-keywords` with structural/generated keyword weights 0/0 and the same 30/20/5 budgets, using the already committed plain vectors. The API gains explicit structural-weight configuration without changing its default. This correction arose from code/source inspection, not an attempt to improve an answer score.

The first baseline source review found substantial unrelated context and generation-dominated latency. After baseline capture, test `structural/primary1` with one primary candidate plus the unchanged mandatory context and neighbor expansion, keeping retrieval/reranking at 30/20. Run both cache passes and retain any quality regression. This is a development ablation, not automatic authorization to make one primary the general default. Offline replay varies candidate budgets 5/10/20/30 and keyword weights using the original captured queries/vectors, with no new model prompts. A separate 400-document/12,800-supplied-vector probe measures capacity only, not realistic corpus quality or PDF/model ingestion.

Raw indexed chunk coverage excludes separately stored source labels. The table column header is stored in `pdf_context` rather than a standalone body chunk, so raw body coverage has a 96.7% ceiling on these ten supported cases. It is already reattached before reranking. Add an explicit `reranked_top5_with_source_labels` metric that incorporates original ancestor headings and deterministic PDF label sources, without neighbors or generated text. Keep the original raw metric beside it; do not call the raw difference a reranker loss. `summarize.py` re-scores preserved raw responses using the current scorer and records its hash; original response files and captured historical scores stay unchanged. Actual table ranking still needs attention: the high-temperature exception outranks the nominal row.

The first `primary1` pass lost the nominal H2 row and returned insufficient evidence for the supported table question. Its source context and assessment confirm an assembly-recall loss rather than hallucination. Retain that full trial, then test `structural/primary2` (both cache passes, all dev questions) because the nominal row ranks second. Preserve 30/20 retrieval/reranking and the original model/prompts. Keep the general default at five primaries; a faster two-primary result on this narrow set is an opt-in experiment pending independent multi-passage evaluation.
